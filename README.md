# Drilly

Browser game prototype for the OpenAI × Tokyo AI 100-Hour Game Challenge, Track 1.
The planned game is a dungeon-building rivalry against an AI opponent. This
baseline contains the Convex + React starter; gameplay is still to come.

## Requirements

- Node.js **24.14.0**, pinned in `.nvmrc` and used by CI.
- npm (included with Node.js); use the committed `package-lock.json`.
- A Convex account with access to the team's Convex project to run the backend.

## Install and start

```sh
git clone git@github.com:twentyone212121/drilly-p.git
cd drilly-p
nvm install
nvm use
npm ci
npm run dev
```

If you do not use nvm, install the Node.js version from `.nvmrc` through your
preferred version manager, then run the npm commands above.

On first startup, follow the Convex CLI login/setup prompts and select the team's
existing project. Ask a teammate for access if it is not listed. Use a development
deployment for local work. The CLI writes the deployment configuration to
`.env.local`, refreshes the generated Convex bindings, and watches backend changes.
The same command starts Vite and opens the browser; use the local URL it prints
(normally `http://localhost:5173`). Stop both processes with Ctrl+C.

The starter's “Add a random number” button provides a quick backend smoke check:
open a second tab and confirm that both tabs show the updated list.

## Environment variables

`.env.example` documents placeholder values. Let the Convex CLI generate your
actual `.env.local`; do not copy a teammate's credentials or commit local env files.

| Variable               | Purpose                                           | Required now?                                        |
| ---------------------- | ------------------------------------------------- | ---------------------------------------------------- |
| `CONVEX_DEPLOYMENT`    | Selects the deployment used by the Convex CLI.    | Yes, for backend development; configured by the CLI. |
| `VITE_CONVEX_URL`      | Public Convex API URL used by the browser client. | Yes, to run the app.                                 |
| `VITE_CONVEX_SITE_URL` | Public base URL for Convex HTTP actions.          | Generated by the CLI; currently unused by the app.   |

All `VITE_` values are public browser configuration. Never put API keys or other
secrets in a `VITE_` variable. When AI integration is added, store `OPENAI_API_KEY`
in the Convex deployment's environment settings and read it only in backend code;
it is not needed for this baseline.

`.gitignore` excludes `.env`, `.env.*` (except `.env.example`), dependencies, and
build output. Before committing, review `git diff --cached` for accidental secrets.

## Checks and builds

```sh
npm run lint
npm run build
```

`lint` checks TypeScript for the frontend, Vite configuration, and Convex functions,
then runs ESLint. `build` repeats the typecheck and produces the frontend in `dist/`.
`npm run typecheck` runs just the TypeScript checks.

GitHub Actions runs `npm ci`, lint, and build on every pull request and on pushes
to `main`. These checks require no Convex login, deployment, or repository secrets.
They verify compilation, not live backend behavior. Generated bindings in
`convex/_generated/` are committed so a fresh checkout can compile without codegen.
Commit updated bindings alongside backend changes after running development codegen.

To preview a runnable production build locally, first configure `.env.local` via
`npm run dev`, then run `npm run build` followed by `npm run preview`. Vite embeds
the public environment values at build time. The backend must already be running
or deployed; building the frontend does not deploy Convex.

## Working together

- Keep changes on short-lived branches and open pull requests into `main`.
- Run lint and build before requesting review.
- Use `npm ci` after pulling dependency changes. When intentionally adding a
  dependency with `npm install`, commit both `package.json` and `package-lock.json`.
- `src/` contains the UI; `convex/` contains the schema and backend functions.
- `AGENTS.md` and the bundled `.agents/skills/` contain the existing
  coding-agent guidance. Read the Convex guidance before editing backend code.

See the [Convex documentation](https://docs.convex.dev/) and
[Vite documentation](https://vite.dev/guide/) for framework details.
